## Introdução — O que é Claude Code

O Claude Code está aparecendo em todo lugar. Você provavelmente já viu alguém usando para criar aplicativos, automatizar tarefas e até ganhar dinheiro com isso. E é uma ferramenta que não precisa saber programar para utilizar.

O Claude Code entra no seu projeto e faz praticamente tudo por você. Só que tem um problema: tudo isso é explicado por gente que já programa. Quem não vem desse mundo abre aquilo, olha a tela e pensa: “Meu Deus, o que está acontecendo aqui?”

Então, é isso que vamos fazer agora: um curso completo de Claude Code para iniciantes.

Você vai aprender 19 conceitos, divididos em quatro blocos, cada um em menos de um minuto. Quando esse vídeo terminar, o Claude Code vai fazer total sentido para você. Bora!

# Bloco 1 — O básico

## 1. O que é Claude Code?

Até agora, o jeito mais comum de usar inteligência artificial era abrir um chat, digitar uma pergunta, receber uma resposta e tchau. ChatGPT, Gemini e o próprio Claude também funcionam assim.

Só que o Claude Code é diferente. Ele não dá uma resposta para você aplicar, porque ele aplica por você.

Pense nele como um cara sentado ao seu lado, olhando para a mesma tela que você e trabalhando junto contigo.

- Em um chat normal: a IA dá uma resposta e você se vira para aplicá-la.
- No Claude Code: ele aplica para você.

Ele lê o que precisa, entende o que precisa mudar e muda.

## 2. O que é terminal?

O Claude Code não roda no navegador como um chat normal. Ele roda dentro do terminal.

“Ah, Paulo, o que é um terminal?”

É aquela tela preta que o programador usa, mas não se preocupe, porque não é coisa de outro mundo. É uma ideia muito mais simples do que parece.

Em vez de clicar em um botão, você digita o que quer fazer. Só isso.

Aqui vem o ponto mais importante: se você está usando o Claude Code, não precisa pensar muito para enviar o comando. Na maior parte do tempo, você só escreve em português mesmo e, às vezes, até com erro ortográfico. Ele vai entender, traduzir isso para o inglês e enviar o que você precisa.

Antigamente, para instalar alguma coisa dentro dessa tela preta, que é o terminal, você precisava digitar alguns comandos, `npm` e não sei o quê. Hoje, você só fala para ele: “Instala para mim”, e ele resolve.

No começo, você precisa saber só de quatro coisas:

1. Como abrir o Claude Code.
2. Como fechar.
3. Como limpar a conversa.
4. Como pedir as coisas diretamente.

O resto você vai aprendendo no caminho, porque o terminal é apenas o lugar onde o Claude Code trabalha. Você não precisa dominá-lo para começar a usar.

## 3. O que é prompt e como pedir melhor?

O prompt é o que você escreve para o Claude. É a sua instrução, simples assim.

Só que aqui tem uma diferença grande: no chat normal, se você pede mal, vai receber uma resposta ruim, não tem jeito. No Claude Code, é preciso ter cuidado, porque ele não apenas responde: ele executa.

Lembra que eu falei no começo? A forma como você pede muda completamente o resultado.

Vamos ver a diferença na prática.

Pedido genérico:

“Faz uma ferramenta de treino para mim.”

Ele vai fazer alguma coisa, mas provavelmente será genérica, sem detalhes e não vai funcionar direito.

Pedido específico:

“Cria uma ferramenta que gere planos de treino semanais baseado em quantos dias eu treino, divisões por grupo muscular.”

A conversa é diferente porque você foi específico. Agora ele sabe exatamente o que você quer.

Quanto mais clareza, detalhes e contexto você fornecer, melhor será o resultado.

## 4. Ferramentas e execução no computador

Por que o Claude Code consegue fazer tanta coisa, diferentemente de um chat normal, como o ChatGPT?

Porque ele tem acesso a ferramentas que se integram diretamente ao seu computador — a tudo do seu computador, para ser sincero.

Com isso, ele consegue modificar, escrever ou adicionar alguma coisa nova. Se precisar corrigir um erro, consegue fazer isso na raiz.

Só que tem uma coisa que torna tudo isso ainda melhor: você não precisa dizer qual ferramenta ele deve usar.

Por exemplo, você pode pedir:

- Organize esta pasta.
- Revise este código.
- Crie uma versão nova.

Ele decide sozinho como chegar ao resultado.

Resumindo: ele não diz o que faria; ele faz e escolhe o caminho para executar.

## 5. Permissões e segurança

“Se ele mexe em tudo, como eu sei que não vai fazer besteira?”

É por isso que existem as permissões.

O Claude Code faz coisas reais no seu computador, mas você precisa controlar o que ele pode e o que não pode fazer.

Existe uma opção em que ele pergunta se pode executar determinada ação. Você clica para aprovar a solicitação.

Só que há um problema: às vezes, você está no meio de um trabalho grande e ele fica perguntando toda hora: “Posso aprovar? Posso aprovar? Posso aprovar?”

Assim, você vê o que ele faz em cada etapa, entende o comportamento e, quando se sentir confortável, vai liberando aos poucos.

Isso é muito perigoso, tá bom? Tome cuidado. É como dar a chave do seu carro para alguém que você nem sabe se sabe dirigir.

## 6. Janela de contexto

Até aqui, parece tudo ótimo. O Claude lê, escreve, executa e trabalha juntinho contigo. Mas existe um limite que você precisa entender, senão vai achar que ele está com defeito.

A janela de contexto é a memória de curto prazo do Claude. É tudo o que ele consegue considerar em determinado momento.

O que isso significa? Tudo aquilo que você escreveu, o que ele respondeu, os arquivos que leu e as mudanças que fez.

Essa memória não é infinita.

Quando a conversa fica longa demais, ele lê muitos arquivos e acumula muitas instruções, a IA começa a se perder, confundir informações, esquecer o que você pediu no começo e misturar um monte de coisas. Com isso, vai ficando ruim e, entre aspas, “mais burra”.

A solução é simples: quando mudar de assunto ou sentir que está ficando pesado demais, comece uma conversa nova. Limpe o contexto e deixe o Claude focar.

Mantendo limpa a memória curta do Claude, você consegue fazê-lo trabalhar melhor.

Também é possível mandar uma mensagem para o Claude pedindo o chat anterior ou informando o nome do chat com o qual você estava dialogando. Isso funciona, mas, no próximo bloco, veremos uma solução melhor.

# Bloco 2 — Contexto e memória

Acabamos de ver que o Claude piora quando acumula informações demais. Agora vamos conhecer as soluções para lidar com isso.

## 7. Contexto compacto

Contexto compacto é basicamente fazer uma faxina na memória dele, resumir o que importa e jogar fora aquilo que não importa mais.

Sabe quando você está assistindo a uma série longa e alguém pergunta: “O que aconteceu aqui?”

Você não vai contar cena por cena, explicando cada detalhe. Vai falar o essencial.

É isso que o Claude vai fazer: focar nos pontos essenciais da sua conversa.

Só que, se ele continuar enrolando ou se perdendo, você vai ter que pedir manualmente que ele recupere aquilo que excluiu, dizendo:

“Olha, você vai ter que pegar essas coisas que você excluiu e me mandar aqui, porque são importantes para mim.”

Ele vai entender.

## 8. Histórico de conversas

Outra coisa útil é que o Claude Code salva o histórico das suas sessões.

Você não precisa começar do zero toda vez que fecha o terminal ou desliga o computador.

Isso parece óbvio, mas faz muita diferença, porque quase ninguém termina um projeto grande em uma única sessão.

O normal é avançar um pouco, fechar, voltar outro dia e continuar. Se toda vez você tivesse que voltar e explicar tudo novamente, seria uma loucura.

Com o histórico, você pula essa parte e retoma de onde tinha parado.

Basta digitar dois tracinhos e `resume` (`--resume`), e ele recupera a conversa anterior. Você segue o trabalho como se não tivesse saído.

Então, o Claude não só lembra do que acontece dentro de uma sessão: ele também permite voltar a sessões anteriores e continuar o trabalho sem recomeçar do zero.

## 9. Claude.md: o arquivo mais importante

Este talvez seja o conceito mais importante do vídeo inteiro. Se você não gravar mais nada, pelo menos grave este, por favor.

Sabe quando você trabalha com alguém e, toda vez que começa uma tarefa, precisa explicar tudo novamente?

“Faça assim, não faça assado, responda desse jeito, priorize isso.”

O arquivo `CLAUDE.md` resolve esse problema, porque é nele que você define como quer que o Claude trabalhe com você naquele projeto.

Você estabelece instruções fixas. Ele lê e passa a segui-las, sem você precisar ficar repetindo mensagens como:

“Responda em português, pare de enrolar e responda diretamente ao ponto.”

Isso acaba com a necessidade de repetir essas instruções.

O `CLAUDE.md` funciona como um pequeno manual pelo qual o Claude vai se orientar.

## 10. Memória

Até agora, quase tudo o que vimos vive dentro de uma conversa ou de um projeto específico. Mas a memória vai além.

A ideia é a seguinte: o Claude não apenas lembra do que está acontecendo naquele chat; ele também vai captando certas preferências suas e carregando isso entre diferentes sessões.

E não, isso não é a mesma coisa que voltar a uma conversa anterior.

Por exemplo, se você conversa com o Claude somente em português, ele pode adaptar o trabalho a essa preferência.

A forma mais fácil de entender é a seguinte:

- `CLAUDE.md`: é aquilo que você decide desde o início. Você escreve as regras.
- Memória: é aquilo que o Claude aprende sozinho com o tempo, com base na maneira como vocês trabalham juntos.

Uma coisa você controla; a outra vai sendo construída ao longo do tempo.

# Bloco 3 — Funções que mudam o jogo

## 11. Modelos: Haiku, Sonnet e Opus

Quando falamos de Claude Code, não estamos falando de apenas um modelo funcionando por baixo. Você pode escolher entre modelos diferentes, e cada um serve melhor para determinado tipo de tarefa.

Existem três modelos que você precisa lembrar: Haiku, Sonnet e Opus.

### Haiku — rapidez e tarefas simples

O Haiku é o mais rápido e leve. É bom para tarefas simples, coisas rápidas e ações pontuais.

Por exemplo:

- Renomear um arquivo.
- Corrigir um texto.
- Fazer perguntas simples.

Ele responde rapidamente e consome menos recursos.

### Sonnet — equilíbrio para o dia a dia

O Sonnet é equilibrado. Tem boa velocidade, boa qualidade e custo intermediário.

É o modelo indicado para o trabalho do dia a dia. A maioria das tarefas que você fizer geralmente será resolvida pelo Sonnet.

### Opus — problemas complexos

O Opus é muito mais forte para problemas complexos, raciocínio intenso e análises profundas.

Ele é o modelo indicado para esse tipo de tarefa, mas também é o mais caro e mais lento.

Você pode pensar: “Então é só usar o Opus para tudo, porque ele é o mais inteligente?”

Não. É como contratar um engenheiro sênior para trocar uma lâmpada para você.

Mas também existe o outro lado: não adianta contratar um estagiário para planejar uma planta de um megaprojeto de prédios. Ele também não vai dar conta.

Cada tarefa exige o nível certo de capacidade.

Para trocar de modelo dentro do Claude Code, basta digitar `/model`. Então, você escolhe:

- Haiku para coisas rápidas.
- Sonnet para o dia a dia.
- Opus para coisas complexas.

## 12. Comandos com barra

Ao longo do vídeo, já usamos vários comandos sem dar nome a eles: `/compact`, `/clear`, `/model` e outros.

Todos têm uma coisa em comum: são comandos com barra dentro do Claude Code.

Em vez de escrever uma frase inteira explicando o que você quer — por exemplo, “limpe esta conversa e comece tudo do zero” —, você digita `/clear` e acabou.

Os principais comandos são:

- `/clear`: limpa a conversa e começa do zero.
- `/compact`: faz aquela faxina na memória que vimos anteriormente.
- `/model`: permite escolher o modelo.
- `/help`: mostra os comandos disponíveis.

O último é especialmente importante no começo. Se você esqueceu tudo, digite `/help`. Ele vai mostrar uma lista dos comandos existentes.

E tem mais uma coisa legal: você pode criar seus próprios comandos.

Se existe uma ação que você executa toda hora, é interessante transformá-la em um comando personalizado, para conseguir trabalhar do seu jeito.

## 13. Capturas de tela e imagens

Existem situações em que explicar um problema por texto faz você perder mais tempo do que simplesmente tirar uma foto e mostrar.

Você já tentou descrever um problema visual por texto?

Por exemplo:

“O botão está desalinhado e a cor está errada. O espaçamento entre o título e o subtítulo está grande demais.”

É bem difícil explicar isso apenas com texto.

O Claude Code entende imagens, não apenas texto. Ele olha para uma captura de tela e interpreta o que está vendo.

Por exemplo, se você tem um problema de design, em vez de escrever dez linhas explicando, pode tirar uma captura da tela, fotografar o problema e enviá-la para ele.

Ele vai identificar diretamente as cores, a estrutura e os botões mal posicionados e poderá resolver o problema para você.

Mas isso também funciona no sentido contrário.

Você pode mostrar um site ou um design de que gosta e dizer:

“Olha, cria algo parecido com isso.”

E ele vai criar.

## 14. MCP explicado

Você já ouviu falar em MCP? Pois é, vou explicar o que é.

É, literalmente, uma conexão com outras ferramentas. O MCP parece um nome técnico complicado, mas a ideia é muito simples.

Até agora, tudo o que o Claude Code faz acontece com base no que existe no seu computador: arquivos, pastas e código do projeto. Ele trabalha com aquilo que está ali.

Só que, na prática, seu trabalho não acontece apenas no computador.

O MCP permite conectar o Claude com ferramentas externas. É uma maneira de dar acesso a outros lugares além do seu computador.

Com MCP, é como se você desse braços maiores para o Claude.

Antes, ele só alcançava o que estava sobre a mesa dele. Agora, consegue alcançar outros recursos porque você lhe deu mais opções para trabalhar.

Tudo fica conectado.

O MCP é a ponte que conecta o Claude com o restante do seu ecossistema. Assim, ele deixa de trabalhar isoladamente e passa a atuar nos ambientes em que seu trabalho realmente acontece.

## 15. Subagentes

Até aqui, quase tudo acontece dentro de uma única conversa, com o Claude fazendo muitas tarefas e lidando com muitas informações.

Só que, quando o trabalho fica grande e há muita coisa acontecendo, um único agente começa a se perder. Já vimos isso quando falamos da janela de contexto.

É aí que entra a ideia de subagentes.

Pense assim: um subagente é um especialista que o Claude chama para resolver uma parte específica do trabalho.

Em vez de fazer tudo sozinho no mesmo fluxo, ele separa uma tarefa e a entrega a outro agente, com seu próprio contexto.

É como se houvesse alguém especializado em fazer aquela atividade.

Pense em um gerente que não tenta fazer tudo sozinho. Ele distribui as tarefas:

“Você vai fazer isso. Você vai fazer aquilo.”

É assim que funciona o subagente.

Existem duas vantagens claras:

1. Qualidade: um agente focado em uma única tarefa pode executá-la melhor do que um agente que tenta fazer tudo.
2. Velocidade: quando o trabalho é dividido, ele pode avançar mais rapidamente.

Na computação, acontece a mesma coisa.

Nem sempre você precisa criar os subagentes manualmente. O Claude Code já vem com subagentes integrados e pode acioná-los automaticamente quando percebe que faz sentido.

Subagentes são especialistas que o Claude chama para ganhar clareza, qualidade e velocidade.

Quanto mais complexo for o projeto, mais útil isso se torna.

## 16. Modo autônomo

Tudo o que vimos até agora tem um objetivo: fazer o Claude trabalhar com cada vez mais independência.

O modo autônomo representa o ponto final desse processo.

A ideia é que, em vez de orientar cada etapa, você forneça um objetivo completo e deixe o Claude trabalhar sozinho.

Imagine que você tenha uma lista inteira de tarefas:

- Criar uma página.
- Adicionar um formulário.
- Melhorar o design.
- Corrigir erros.

Em vez de orientar uma tarefa por vez, você dá uma única instrução:

“Analise o projeto, complete essas tarefas, revise o resultado e otimize.”

A partir daí, ele executa o processo inteiro.

Mas você pode perguntar: “Paulão, ele vai sempre acertar?”

Não. Às vezes, ele vai seguir um caminho diferente daquele que você queria. Pode interpretar uma parte de forma errada ou fazer algo desnecessário.

É aí que você entra e ajusta o resultado.

Você passa a atuar como um supervisor, e não como um operador. Em vez de executar cada tarefa, acompanha e direciona o trabalho.

Portanto, não se trata de ele fazer tudo perfeitamente, mas de avançar muito trabalho enquanto você acompanha.

O volume de coisas que ele resolve sozinho é muito maior do que se você ficasse orientando cada passo.

# Bloco 4 — Controle, segurança e custos

## 17. Checkpoints

Existe uma coisa importante: o Claude nem sempre acerta.

Quando você começa a utilizá-lo para fazer mudanças reais no projeto, ele pode alterar muitas coisas muito rapidamente. Se fizer alguma alteração errada, você precisa de uma maneira de voltar atrás.

É aí que entram os checkpoints.

Um checkpoint é basicamente um ponto de salvamento automático. Antes de fazer uma mudança importante, o Claude salva uma imagem do estado anterior do projeto, para que você possa recuperá-lo depois, se precisar.

O bom é que isso funciona sozinho, em segundo plano. Você não precisa ficar ativando nem configurando nada.

Se algo quebrar ou o resultado não agradar, digite `/rewind`. Ele vai mostrar os pontos aos quais você pode voltar dentro daquela sessão.

Você escolhe o momento e restaura. Assim, tudo volta a ficar como estava.

É como o `Ctrl + Z` da vida, só que muito mais poderoso, porque não serve apenas para desfazer a última ação: você pode voltar a um ponto anterior da sessão.

Isso é muito bom porque permite testar sem medo.

Às vezes, ficamos preocupados: “Nossa, e se eu fizer isso e não conseguir mais voltar atrás no projeto?”

Com os checkpoints, você tem uma maneira de recuperar estados anteriores e experimentar mudanças com mais tranquilidade.

## 18. Git: rede de segurança

Existe outro conceito importante quando você começa a usar o Claude Code de verdade no dia a dia: controlar tudo o que ele vai modificando.

Você precisa saber:

- O que mudou.
- Quando mudou.
- Por que mudou.

É aí que entra o Git.

O Git funciona como um histórico das mudanças do seu projeto. As alterações registradas permitem acompanhar o que foi feito, quem fez, quando foi feito, como era antes e como ficou depois.

Pense no Git como uma câmera de segurança do projeto. Tudo o que for registrado fica guardado ali.

Se alguém ou o Claude fizer alguma coisa que não deveria, você pode consultar o histórico, verificar exatamente o que aconteceu e reverter a mudança, se necessário.

### Qual é a diferença entre checkpoint e Git?

O checkpoint funciona dentro de uma sessão. É como uma maneira de desfazer alterações rapidamente enquanto você está trabalhando.

O Git funciona como um histórico de longo prazo.

Mesmo que você feche tudo, desligue o computador e volte na semana seguinte, as alterações registradas no Git continuam disponíveis.

E o mais importante: você não precisa ser especialista em Git para começar a utilizá-lo, porque, em muitos casos, ele pode funcionar em segundo plano.

Se precisar voltar atrás algum dia, o histórico estará lá.

O Git é uma das ferramentas que ajudam você a trabalhar com mais tranquilidade.

## 19. Custos e limites

Este é o último ponto, e muita gente o ignora: quanto custa o Claude Code?

Ele é muito bom, mas não é gratuito. Se você não entender como funciona o pagamento, pode levar um susto na fatura.

Existem dois caminhos.

### Opção 1 — Plano mensal

A Anthropic, empresa responsável pelo Claude, oferece planos mensais.

Na transcrição, são mencionados:

- Plano Pro: a partir de US$ 20 por mês.
- Plano Max: de US$ 100 a US$ 200 por mês, com mais capacidade e possibilidade de enviar mais mensagens.

Você paga um valor fixo e utiliza o serviço dentro dos limites do plano.

Observação: esses são os valores mencionados pelo apresentador no vídeo, não uma confirmação dos preços ou limites vigentes atualmente.

### Opção 2 — Créditos de API

Aqui não existe uma mensalidade fixa pelo consumo da API. Se você utilizar pouco, gastará pouco.

Surge então a pergunta: o que compensa mais, pagar o plano inteiro ou pagar pelo que você utiliza?

A resposta depende da frequência de uso.

- Uso ocasional: pode compensar pagar pelo consumo, porque você não gastará muito.
- Uso frequente: a mensalidade pode fazer mais sentido, principalmente se você pretende utilizar a ferramenta continuamente e o valor couber no seu orçamento.

### Escolha o modelo de acordo com a tarefa

Existe outro fator importante: dependendo do modelo escolhido, o custo muda.

Lembra dos três modelos que vimos anteriormente?

Haiku, Sonnet e Opus.

O Haiku é o mais barato, enquanto o Opus é o mais caro.

Se a tarefa for simples, você não precisa usar o Opus. Pode usar o Haiku e economizar.

O Claude Code compensa muito quando economiza seu tempo.

Se uma tarefa que levaria três horas passa a levar vinte minutos com ele, o custo pode se pagar facilmente.

O Haiku é indicado para perguntas e tarefas simples, com menor consumo. Assim, você consegue utilizar a ferramenta por mais tempo dentro do seu orçamento.

A ideia final é esta: a ferramenta é poderosa, mas, quando você escolhe quando e como utilizá-la, consegue melhores resultados e controla melhor os custos.
